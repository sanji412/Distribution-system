# 企业级智能分销与订单履约平台 Prompt 模板与接口文档

## 一、文档说明

本文档用于说明企业级智能分销与订单履约平台当前已经实现的后端接口，以及 AI 客服模块使用的 Prompt 模板、意图识别规则和槽位提取规则。

系统采用 Spring Cloud Alibaba 微服务架构，包含用户服务、商品服务、库存服务、订单服务、支付服务和网关服务。AI 客服能力内嵌在订单服务中，通过 DeepSeek 大模型完成用户问题理解和自然语言回复。

接口文档字段包含：

- 接口名称
- 所属服务
- 请求路径
- 请求方式
- 参数列表

## 三、AI 客服接口重点说明

AI 客服入口：

```http
POST /api/order/ai/chat
```

请求体示例：

```json
{
  "userId": 1,
  "message": "我的订单DD202507010001到哪了？"
}
```

响应数据核心字段：

| 字段名 | 类型 | 说明 |
|---|---|---|
| `reply` | String | AI 客服最终回复内容 |
| `intent` | String | 识别出的用户意图 |
| `slots` | Object | 槽位提取结果 |
| `complete` | Boolean | 槽位是否完整 |
| `dataSource` | String | 回复所依据的数据来源 |
| `modelUsed` | String | 使用的大模型名称或本地降级标识 |
| `createTime` | LocalDateTime | 回复生成时间 |

Prompt 模板查询接口：

```http
GET /api/order/ai/prompt-template
```

该接口用于展示当前 AI 客服使用的意图识别 Prompt、基础客服 Prompt、订单物流动态 Prompt 和库存查询动态 Prompt。

## 四、意图与槽位文档

### 4.1 可识别意图列表

| 意图英文标识 | 意图中文名称 | 对应接口 | 触发场景说明 |
|---|---|---|---|
| `order_logistics` | 订单物流查询 | `/api/order/remote-detail/{orderNo}` | 用户询问订单发货状态、物流轨迹、当前位置、预计送达时间 |
| `goods_stock` | 商品库存查询 | `/api/stock/product/{productId}` | 用户询问某个商品是否有货、库存数量、是否缺货 |
| `product_consult` | 商品详情咨询 | `/api/product/{productId}` | 用户询问某个商品价格、分类、规格、参数或描述 |
| `other` | 兜底意图 | 无对应业务接口 | 用户问题超出当前电商客服业务范围，或无法识别 |

### 4.2 分意图槽位提取规则

#### 4.2.1 `order_logistics` 订单物流查询

| 槽位字段名 | 类型 | 是否必填 | 来源接口入参 | 说明 |
|---|---|---|---|---|
| `orderNo` | String | 必填 | `/api/order/remote-detail/{orderNo}` | 订单编号，例如 `DD202507010001` |

槽位完整时，系统会查询订单主表中的订单状态、物流公司、物流单号、物流状态、当前位置和预计送达时间，再生成动态 Prompt。

槽位缺失时，追问话术：

```text
亲亲，请提供一下订单号哦~
```

#### 4.2.2 `goods_stock` 商品库存查询

| 槽位字段名 | 类型 | 是否必填 | 来源接口入参 | 说明 |
|---|---|---|---|---|
| `productId` | Long | 必填 | `/api/stock/product/{productId}` | 商品 ID，例如 `1` |

槽位完整时，系统会调用商品服务查询商品信息，并调用库存服务查询各仓库库存数量。

槽位缺失时，追问话术：

```text
亲亲，请提供一下商品ID，我才能帮你查询实时库存哦~
```

#### 4.2.3 `product_consult` 商品详情咨询

| 槽位字段名 | 类型 | 是否必填 | 来源接口入参 | 说明 |
|---|---|---|---|---|
| `productId` | Long | 必填 | `/api/product/{productId}` | 商品 ID，例如 `1` |

槽位完整时，系统会调用商品服务查询商品名称、分类、价格、SKU、描述、状态和安全库存等信息。

槽位缺失时，追问话术：

```text
亲亲，请提供一下商品ID哦~
```

#### 4.2.4 `other` 兜底意图

| 槽位字段名 | 类型 | 是否必填 | 来源接口入参 | 说明 |
|---|---|---|---|---|
| 无 | 无 | 无 | 无 | 不需要业务参数 |

兜底回复话术：

```text
抱歉亲亲，我只能解答购物相关的问题哦~
```

## 五、Prompt 模板文档

### 5.1 电商客服基础 Prompt 模板

```text
【角色人设】
你是优选电商的官方在线客服，称呼用户为「亲亲」，语气亲切、耐心、专业，使用生活化口语表达。

【业务范围】
仅可解答订单物流、商品咨询、库存查询、活动规则四类问题。
超出以上范围的问题，统一回复：「抱歉亲亲，我只能解答购物相关的问题哦~」

【回复要求】
1. 回复简洁易懂，控制在150字以内
2. 涉及步骤时用数字序号分点说明
3. 禁止编造平台规则、优惠活动、物流信息
4. 禁止与用户争吵、禁止使用不礼貌用语

【用户当前问题】
{userMessage}
```

### 5.2 意图识别与槽位提取 Prompt 模板

```text
你是电商系统的需求分析师，严格基于下方提供的【微服务清单】【核心建表字段】【Controller层用户侧接口文档】，生成C端AI客服的语义提取结果。

【硬性约束】
1. 只基于提供的材料推导，严禁新增任何文档里没有的接口、字段和业务能力
2. 一个用户侧查询接口对应一个核心意图，意图命名和接口功能对齐
3. 槽位字段名必须和Controller接口的入参名称完全一致，必填/可选属性和接口保持统一
4. 剔除鉴权类公共参数（如token、userId），只保留用户对话中会提到的业务参数
5. 必须补充other兜底意图，覆盖所有接口外的无关问题

【可识别意图列表】
1. order_logistics：订单物流查询，对应接口 /api/order/remote-detail/{orderNo}，必填槽位 orderNo
2. goods_stock：商品库存查询，对应接口 /api/stock/product/{productId}，必填槽位 productId
3. product_consult：商品详情咨询，对应接口 /api/product/{productId}，必填槽位 productId
4. other：无法识别或超出当前 Controller 能力范围的问题

【核心建表字段】
order_main：order_no、product_name、product_num、order_status、logistics_company、logistics_no、logistics_status、current_location、expect_arrive_time
product：product_id、product_name、category、price、sku_code、description、status、safe_stock
stock：product_id、warehouse_id、stock_num

【Controller层用户侧接口文档】
接口名称：订单跨服务详情查询
接口路径：/api/order/remote-detail/{orderNo}
请求方式：GET
入参列表：
- orderNo：String，必填，订单编号

接口名称：商品详情查询
接口路径：/api/product/{productId}
请求方式：GET
入参列表：
- productId：Long，必填，商品ID

接口名称：商品库存查询
接口路径：/api/stock/product/{productId}
请求方式：GET
入参列表：
- productId：Long，必填，商品ID

【输出格式】
严格输出纯JSON，无任何多余字符，字段定义如下：
{
  "intent": "order_logistics/goods_stock/product_consult/other",
  "slots": {
    "orderNo": "提取到的订单号，未提取到则为null",
    "productId": "提取到的商品ID，未提取到则为null"
  },
  "is_complete": true,
  "reply_tip": "参数完整为null；缺失则返回亲切的追问话术；无关问题返回「抱歉亲亲，我只能解答购物相关的问题哦~」"
}

用户提问：{{用户输入内容}}
```

## 六、AI 客服处理流程

```text
用户发送问题
    ↓
调用意图识别与槽位提取 Prompt
    ↓
根据 intent 判断业务类型
    ↓
检查必填槽位是否完整
    ↓
槽位缺失：返回追问话术
槽位完整：调用对应业务接口查询真实数据
    ↓
把真实业务数据填入动态 Prompt
    ↓
调用 DeepSeek 生成自然语言客服回复
    ↓
保存 AI 对话记录并返回前端
```

## 七、示例

### 7.1 订单物流查询示例

用户问题：

```text
我的订单DD202507010001到哪了？
```

意图识别结果：

```json
{
  "intent": "order_logistics",
  "slots": {
    "orderNo": "DD202507010001"
  },
  "is_complete": true,
  "reply_tip": null
}
```

系统处理：

```text
调用 /api/order/remote-detail/{orderNo} 查询订单履约和跨服务聚合信息，
再基于订单真实物流数据生成客服回复。
```

### 7.2 商品库存查询示例

用户问题：

```text
商品ID 1 现在还有库存吗？
```

意图识别结果：

```json
{
  "intent": "goods_stock",
  "slots": {
    "productId": "1"
  },
  "is_complete": true,
  "reply_tip": null
}
```

系统处理：

```text
调用 /api/product/{productId} 查询商品信息，
调用 /api/stock/product/{productId} 查询库存信息，
再基于真实库存数据生成客服回复。
```

### 7.3 槽位缺失示例

用户问题：

```text
我的快递到哪了？
```

意图识别结果：

```json
{
  "intent": "order_logistics",
  "slots": {
    "orderNo": null
  },
  "is_complete": false,
  "reply_tip": "亲亲，请提供一下订单号哦~"
}
```

系统处理：

```text
由于缺少必填槽位 orderNo，不调用业务接口，直接返回追问话术。
```
