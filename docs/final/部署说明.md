# 企业级智能分销与订单履约平台部署说明

## 1. 部署目标

本项目提供 Docker Compose 一键启动方案，用于在本机或另一台演示电脑上快速启动完整系统。

启动内容包括：

- MySQL 8.0
- Redis 7
- Nacos 注册中心
- Seata TC 服务
- user-service
- product-service
- stock-service
- order-service
- pay-service
- auth-service
- gateway-service
- Vue3 前端静态服务

## 2. 环境要求

演示电脑需要提前安装：

- Docker Desktop
- Docker Compose
- Git

默认使用以下宿主机端口。如果演示电脑上有端口被占用，可以在 `.env` 中修改对应的 `*_HOST_PORT`：

| 默认端口 | `.env` 变量 | 服务 |
| --- | --- | --- |
| 5173 | `FRONTEND_HOST_PORT` | 前端页面 |
| 9000 | `GATEWAY_HOST_PORT` | Gateway 网关 |
| 8848 | `NACOS_HOST_PORT` | Nacos 控制台 |
| 9848 | `NACOS_GRPC_HOST_PORT` | Nacos gRPC |
| 7091 | `SEATA_CONSOLE_HOST_PORT` | Seata 控制台 |
| 8091 | `SEATA_HOST_PORT` | Seata TC |
| 3307 | `MYSQL_HOST_PORT` | MySQL |
| 6379 | `REDIS_HOST_PORT` | Redis |
| 8001 | `USER_SERVICE_HOST_PORT` | user-service |
| 8002 | `PRODUCT_SERVICE_HOST_PORT` | product-service |
| 8003 | `STOCK_SERVICE_HOST_PORT` | stock-service |
| 8005 | `ORDER_SERVICE_HOST_PORT` | order-service |
| 8006 | `PAY_SERVICE_HOST_PORT` | pay-service |
| 8007 | `AUTH_SERVICE_HOST_PORT` | auth-service |

## 3. 首次启动

在项目根目录执行：

```bash
cp .env.example .env
```

如果需要 DeepSeek AI 客服在线回复，编辑 `.env`，填写真实 API Key：

```properties
DEEPSEEK_API_KEY=你的真实 DeepSeek API Key
```

如果本机端口冲突，也可以直接在 `.env` 中修改端口，例如：

```properties
FRONTEND_HOST_PORT=15173
GATEWAY_HOST_PORT=19000
MYSQL_HOST_PORT=13307
NACOS_HOST_PORT=18848
REDIS_HOST_PORT=16379
```

然后执行一键启动脚本：

```bash
./scripts/docker-up.sh
```

脚本默认使用 Docker 经典构建器，以兼容部分 Docker Desktop 版本中 BuildKit session 异常的问题。

首次启动会自动构建后端 Jar、构建前端静态资源、初始化 MySQL 表结构和模拟数据，耗时会比普通启动更久。后端 Jar 会先生成到 `distribution-platform/docker-build-jars/`，该目录是构建缓存产物，不需要提交到 Git。

如果演示电脑没有安装 Java，脚本会自动使用 Docker Maven 镜像完成后端打包。

## 5. 启动后验证

启动完成后执行：

```bash
./scripts/docker-smoke.sh
```

该脚本会检查：

- 前端页面是否可访问
- Gateway 登录接口是否返回 token
- 服务治理接口是否可访问
- 商品接口是否可访问
- 库存接口是否可访问
- 订单看板接口是否可访问
- AI 推荐接口是否可访问

## 6. 停止服务

停止但保留数据库数据：

```bash
./scripts/docker-down.sh
```

停止并清空 Docker 数据卷：

```bash
./scripts/docker-down.sh --volumes
```

如果需要重新初始化数据库，可以先清空数据卷再启动：

```bash
./scripts/docker-down.sh --volumes
./scripts/docker-up.sh
```

## 9. 常见问题

### 9.1 端口被占用

如果本地 IDEA 中已经启动了某个服务，Docker 启动可能会报端口占用。可以先停止 IDEA 中的服务，也可以修改 `.env` 中对应的 `*_HOST_PORT`。

查看端口占用：

```bash
lsof -i :9000
lsof -i :8005
```

例如 Gateway 端口被占用时，可以把 `.env` 改成：

```properties
GATEWAY_HOST_PORT=19000
```

然后重新执行 `./scripts/docker-up.sh`。脚本和 `./scripts/docker-smoke.sh` 会自动读取 `.env` 中的新端口。

### 9.2 MySQL 初始化数据没有变化

Docker 的 MySQL 数据保存在 `mysql-data` 数据卷中。SQL 初始化脚本只会在第一次创建数据卷时执行。

如需重新初始化：

```bash
./scripts/docker-down.sh --volumes
./scripts/docker-up.sh
```

### 9.3 AI 客服显示降级

通常有两种原因：

- `.env` 中没有配置真实 `DEEPSEEK_API_KEY`
- 当前网络无法访问 DeepSeek API

业务系统仍可正常使用，AI 客服会返回本地降级结果。

### 9.4 Nacos 页面暂时没有服务

刚启动时后端服务还在构建或注册，等待 30 到 60 秒后刷新 Nacos 控制台。

### 9.5 Docker BuildKit 报错

如果手动执行 `docker compose build` 时遇到 BuildKit gRPC session 相关报错，可以使用：

```bash
DOCKER_BUILDKIT=0 docker compose build
```

`./scripts/docker-up.sh` 已经默认做了这个兼容处理。

### 9.6 手动 Docker build 提示缺少 Jar

后端镜像只复制已经打好的 Jar。手动构建前先执行：

```bash
./scripts/build-backend-jars.sh
```

然后再执行：

```bash
DOCKER_BUILDKIT=0 docker compose build
```

### 9.7 Docker Hub 下载慢或失败

Compose 中的基础镜像已经使用 DaoCloud 镜像地址，减少演示电脑首次拉取镜像失败的概率。Nacos 和 Seata 镜像指定了 `linux/amd64` 平台，在 Apple Silicon 电脑上首次启动会稍慢一些，等待容器启动完成即可。
