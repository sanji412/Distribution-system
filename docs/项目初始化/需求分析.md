# 企业级智能分销与订单履约平台 业务分析与数据库表设计方案（终版）

本方案严格匹配大三实验班实训项目定位，基于 SpringCloud Alibaba 微服务架构与 DDD 领域拆分原则设计，完整覆盖演示系统全部功能模块，不引入超范围技术栈、不扩展额外业务、不增加冗余安全设计，完全适配 48 课时实训教学节奏与答辩演示要求。

## 一、完整业务分析

### 1.1 项目整体概述

企业级智能分销与订单履约平台是面向软件工程专业大三学生的微服务工程实战项目，覆盖**商品分销、订单创建、库存扣减、支付履约、物流跟踪、AI 智能客服**全链路业务流程。

项目基于 SpringCloud Alibaba 技术栈实现微服务架构落地，核心包含 Nacos 注册配置中心、Gateway 统一网关、OpenFeign 远程调用、Seata 分布式事务、Sentinel 限流降级五大核心组件，配套 Redis 做热点数据缓存与调用量统计，同时接入 DeepSeek 大模型实现智能问答与业务推荐。项目从单体架构逐步演进为 5 个微服务的分布式架构，配套前端 Vue3 数据看板与管理后台，完整还原企业级分销系统的技术实现与业务流程。

### 1.2 架构演进路径（贴合实训每日教学节奏）

项目采用渐进式教学路径，从单体到微服务逐步迭代，对应 10 天实训进度：

1. **单体筑基阶段（Day1）**：单 SpringBoot 应用 + 单业务数据库，所有模块同项目同库，实现商品、库存、订单的基础 CRUD 与本地事务，跑通 “创建订单→扣减库存→查询订单” 完整单体流程
2. **服务拆分阶段（Day2）**：按 DDD 领域拆分原则，拆分为 5 个独立业务子模块，数据库垂直拆分为 5 个独立业务库，各服务独立端口部署、独立启动
3. **服务治理阶段（Day3-Day5）**：依次接入 Nacos 注册配置中心、OpenFeign 远程调用、Gateway 统一网关，实现服务注册发现、跨服务调用、统一鉴权与路由转发
4. **事务保护阶段（Day7-Day8）**：接入 Seata 分布式事务保障数据一致性，接入 Sentinel 实现限流降级与服务熔断
5. **AI 与整合阶段（Day9-Day10）**：接入 DeepSeek AI 智能客服，完成前后端联调与 Docker 编排，最终答辩交付

### 1.4 核心技术组件职责

完整覆盖实训指定技术栈，所有组件均对应明确的业务与教学场景：

1. **Nacos 2.3**：服务注册与发现中心 + 配置中心，管理所有服务实例，统一管理数据库、Redis 等公共配置，支持配置热更新

2. **SpringCloud Gateway**：系统唯一入口，实现 5 条动态路由转发（/api/user、/api/product、/api/stock、/api/order、/api/pay）、JWT 统一鉴权、全局跨域处理、路由断言匹配

3. **OpenFeign + Ribbon**：声明式 HTTP 远程调用，自带轮询负载均衡，支持超时重试与降级回调，实现订单服务对库存、支付、商品服务的跨服务调用

4. **Seata 1.7（AT 模式）**：分布式事务协调器，通过 TC/TM/RM 角色配合，基于`undo_log`实现自动数据回滚，保障订单 - 库存 - 支付跨服务数据一致性

5. **Sentinel 1.8**：流量防护组件，提供 QPS 限流、熔断降级、热点参数限流能力，保护核心接口不被流量冲垮

6. Redis 7.0

   ：热点数据缓存与计数组件，承担三个实训场景：

   - 热点商品列表缓存，降低商品服务数据库压力
   - 库存数据预热，提升库存查询接口响应速度，配合压测场景
   - 服务调用量计数，为数据看板 “今日各服务调用量” 提供数据支撑

7. **DeepSeek API**：大语言模型能力入口，通过 RestTemplate/WebClient 调用，实现自然语言问答与推荐生成

### 1.5 核心业务流程

#### （1）正向订单履约流程（Seata 分布式事务提交场景）

1. 用户选品提交订单，订单服务生成初始待支付订单记录
2. 订单服务通过 OpenFeign 调用库存服务，扣减对应商品的可用库存
3. 调用支付服务生成对应金额的待支付支付单
4. 全链路无异常，Seata 全局事务提交，订单状态生效
5. 用户完成支付后，支付回调接口更新支付单状态为「支付成功」，同步更新订单状态为「已支付」
6. 仓库发货后录入物流信息，订单状态流转为「已发货」，同步更新物流位置与预计送达时间
7. 用户签收确认后，订单状态更新为「已完成」

> 对应演示场景：订单 DD202505190001 的完整成功履约链路

#### （2）异常订单回滚流程（Seata 分布式事务回滚场景）

1. 用户提交订单，订单服务生成订单记录
2. 调用库存服务扣减库存时，触发库存不足异常或服务异常
3. 异常向上抛出，Seata 事务管理器通知全局回滚
4. 各服务通过数据库`undo_log`表自动恢复数据，订单记录回滚撤销
5. 订单最终标记为「库存不足」异常状态

> 对应演示场景：订单 DD202505190004 的失败回滚链路

#### （3）AI 智能客服与推荐流程

1. **订单物流问答**：用户输入自然语言问题，后端识别意图后查询订单与物流数据，拼接结构化 Prompt 调用 DeepSeek API，生成自然语言回复返回前端
2. **搭配推荐**：拉取用户近期浏览商品记录，拼接 Prompt 调用大模型，生成商品搭配建议
3. **库存预警**：对比商品当前库存与安全库存阈值，对低于阈值的商品生成补货提醒
4. **热销趋势**：统计近 7 天商品销量，对销量增长显著的商品生成采购建议

> 对应演示场景：AI 客服对话窗口、底部三类智能推荐卡片

#### （4）限流降级与服务保护流程

针对 4 个核心接口配置 Sentinel 规则，完全匹配演示界面监控数据：

- `/api/stock/deduct`（库存服务 - 库存扣减）：QPS 阈值 100，快速失败策略
- `/api/order/create`（订单服务 - 订单创建）：QPS 阈值 200，匀速排队策略
- `/api/pay/callback`（支付服务 - 支付回调）：QPS 阈值 50，快速失败策略
- `/api/product/list`（商品服务 - 商品列表）：QPS 阈值 500，直接拒绝策略

高并发场景下超出阈值的请求直接被拒绝，保护后端服务稳定性；当下游服务宕机或响应超时时，OpenFeign 触发降级回调，返回友好提示，避免故障级联扩散。

#### （5）数据看板统计流程

所有统计数据均从业务表与 Redis 聚合计算，不新增独立统计服务：

- 核心指标：今日订单量、成交额、待发货 / 异常订单数，从订单表按当日维度聚合
- 服务调用量：从 Redis 计数器统计各服务当日请求量
- 订单状态分布：按订单状态分组计算占比
- 近 7 天订单趋势：按日期维度，统计每日订单总量的变化趋势

### 1.6 系统模块边界划分

明确业务功能与架构治理的边界，避免设计混淆：

- **业务功能模块**：订单履约、数据看板、AI 客服，承载核心分销业务逻辑，对应业务数据库表，需要学生编码实现
- **架构治理模块**：服务治理、系统监控，基于 Nacos、Gateway、Sentinel 等组件的原生能力实现，不新增业务表，仅通过组件接口采集数据展示，对应实训的微服务治理知识点

## 二、数据库表设计方案

### 2.1 设计原则

1. **垂直分库**：每个微服务对应独立数据库，严格遵循微服务数据边界，服务间仅通过接口交互，禁止跨库直连
2. **精简实用**：贴合实训项目定位，保留核心业务字段，不引入过度复杂设计，满足功能演示需求
3. **事务支撑**：参与全局事务的业务库内置 Seata AT 模式所需的`undo_log`表，支撑分布式事务回滚演示
4. **适度冗余**：订单表冗余商品名称、数量等字段，减少跨服务查询与联表操作，适配实训开发难度
5. **实训适配**：不增加复杂的权限、审计、软删除等企业级冗余设计，聚焦核心微服务与业务知识点

### 2.6 核心查询索引设计

针对实训高频查询场景设计，符合企业级规范且不增加开发复杂度：

- `sys_user`：`username` 唯一索引（登录场景高频查询）
- `browse_history`：`user_id + browse_time` 联合索引（按用户倒序查询最近浏览记录）
- `stock`：`product_id + warehouse_id` 联合唯一索引（单商品单仓库唯一库存记录）
- `order_main`：`order_no` 唯一索引、`user_id` 普通索引、`order_status` 普通索引、`create_time` 普通索引（时间范围统计）
- `order_item`：`order_id` 普通索引、`product_id` 普通索引（商品销量统计）
- `payment`：`order_no` 唯一索引（通过订单号查询支付单）
- `ai_chat_record`：`create_time` 普通索引（按日期统计 AI 调用次数）
